(1) The "time" command reports real, user, and sys time. In my run, real time was about 6 ms, user time was under 1 ms, and sys time was about 3 ms. This was quite consistent through multiple runs.

(2) The pthread implementation divides the file into chunks and starts one worker per chunk. The count workers calculate a local count and update a shared count while holding the same mutex. The instance workers append matching lines to a shared result while holding its mutex, which protects both the list and its counters. I avoided data races by locking around shared updates and joining the workers before returning or using their results.

(3) The pthread implementation explicitly creates and joins threads and uses mutexes to protect shared results. In the OpenMP implementation, "#pragma omp parallel for" distributes chunk indexes among threads. Each loop iteration writes to its own chunk result, so threads do not need a mutex. After the loop, the program combines the chunk results. Significantly faster than mutex-based exceution as it avoids locking and unlocking overhead.
